# Contributing

## Overview

Contributions to AutoMR are welcome. Please follow the project structure and coding conventions to maintain consistency.

---

# Development Workflow

1. Fork the repository.
2. Create a feature branch.
3. Implement the proposed changes.
4. Add or update documentation.
5. Test the implementation.
6. Submit a pull request.

---

# Coding Standards

- Follow PEP 8.
- Use descriptive variable names.
- Write modular code.
- Keep functions focused on a single responsibility.
- Add docstrings where appropriate.

---

# Testing

Before submitting changes:

- Verify that existing functionality is not affected.
- Test new transformations and relations.
- Execute AutoMR on a sample dataset.
- Review generated reports.

---

# Documentation

When introducing new functionality:

- Update the relevant documentation.
- Include usage examples where appropriate.
- Document public APIs.

---

# Issue Reporting

When reporting issues, include:

- Operating system
- Python version
- Framework version
- Error message
- Reproduction steps

---

# Pull Request Checklist

- Code compiles successfully.
- Tests pass.
- Documentation updated.
- No unnecessary files included.
- Commit messages are descriptive.
